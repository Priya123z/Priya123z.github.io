How I structure automation

Four layers, each allowed to call only the one below it. The point is that a failure tells you where to look before you open anything: a broken selector can only be in the page layer, a wrong expectation can only be in the test.

Tests may call flows
tests/ui/tests/api/

Reads like the requirement. Holds assertions and nothing else — no selectors, no URLs, no waits.

Flows may call pages
flows/auth_flow.pyflows/product_flow.py

Multi-step journeys written once. Register, log in, add to cart, check out — so twelve tests share one path through the app.

Pages and API clients may call services
pages/cart_page.pyapi/api_client.pymodels/

The only place that knows what the app looks like. Every selector and endpoint lives here, so a redesign touches one file per screen.

Shared services calls nothing above
config_managerbrowser_factoryauthentication_managerartifact_manager

Singletons and factories behind fixtures. A test never builds a browser or reads an env file; it asks for a page and gets one.

Evidence written by every layer
alluretracesscreenshotslogs

Everything lands in one run folder, keyed on a single execution id shared by all workers. A failure arrives as a trace you can replay, not a stack line.

That last part was a real bug. Each parallel worker is its own process, and each one used to stamp its own timestamp, so a run split across two folders and CI could publish the empty one. One shared id fixed it.
